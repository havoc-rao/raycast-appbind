# Explicit resident helper service

The argv interface is separate from the existing bounded stdin protocol. `execute` on stdin remains disabled and never posts input.

```
appbind-helper service-start --directory /absolute/private/support
appbind-helper service-status --directory /absolute/private/support
appbind-helper service-reload --directory /absolute/private/support
appbind-helper service-stop --directory /absolute/private/support
```

Each command emits one JSON line: `{ "ok": true, "data": { "running": false, "executionEnabled": false, "accessibilityTrusted": false, "inputMonitoringTrusted": false, "enabledBindings": 0, "configDigest": null, "lastError": null, "pid": null } }`, or `{ "ok": false, "error": { "code": "...", "message": "..." } }`. No login item is installed. `service-run` is an internal child-process entry; it expires after seven seconds without a controller commit. Startup failure terminates only the exact Process child, never a PID file. A failed initial commit response stops the child. As with any local IPC, losing the controller after a successfully delivered commit response is not an atomic distributed transaction.

The support directory must be owned by the current UID and mode 0700; ancestors must be root/current-user owned, not group/world writable, and contain no symbolic links. Config must be a same-UID, single-link regular file, not group/world writable, at most 1 MiB. It is read via directory-relative no-follow descriptors. SHA256 covers original bytes, including whitespace/newlines. Reload clears rules and digest before reading: an invalid replacement cannot leave old rules active. A secure exclusive flock controls socket creation; same-UID peer credentials are checked both ways. Socket mode is 0600. Directory-relative Unix addresses avoid macOS sun_path length limits for long Raycast support paths. IPC requests/replies are bounded, with a one-second whole-message read deadline; the daemon pumps its run loop while waiting and nonblocking replies cannot block event handling.

A start with unavailable permissions remains running but execution-disabled. No permission prompt is made. Permissions and Secure Input are rechecked. Secure Input temporarily pauses execution and cancels old execution tokens; when it ends, valid permissions/configuration and an enabled tap allow automatic recovery (including re-enabling a tap disabled during the pause). Permission loss or an unrelated disabled tap remains latched, requiring explicit reload/restart. `executionEnabled` describes the service gate, not a promise that any particular app is supported. Status is not proof a pending click will succeed.

The tap pairs swallowed down/repeat/up, matches the active ASCII-capable keyboard layout just like recording, rechecks foreground PID/bundle, and queues at most one worker. AX calls are off the tap callback. A trigger snapshots the frontmost normal CG window ID, and a delayed worker (>250 ms) refuses. The worker waits up to two seconds for trigger/modifier release, repeatedly checks the same AX focused window and PID, standard/nonmodal/nonminimized attributes, sheets, geometry and half-open display/window containment. System-wide AX hit testing must identify the same PID/window and CG front-to-back ordering must prove the point is unobscured. An occlusion refusal names the window that claimed the point (`Target point is covered by another CG window: <app> (pid N, layer L, x,y W×H)`, plus a same-app note), because rectangle maths alone cannot separate a real occluder from a rounded corner or a transparent helper window. The name is resolved from the PID through `NSRunningApplication`; window titles are never read and an unresolvable PID is reported as `unknown app`.

**Compatibility is deliberately conservative:** when `AXWindowNumber` is present it must match the trigger CG ID. When absent, the focused window must be the unique exact-frame match in the application's bounded AX window list, and the unique visible normal same-PID exact-frame match in the CG list must have the trigger ID. AX hit-test ownership, CFEqual identity across stages and CG occlusion checks still apply. Invalid present IDs never fall back. This is a constrained identity inference, not an OS-provided AX/CG identity guarantee; ambiguous or unavailable metadata is refused. This is not all-app support. WindowServer/app state and posted events cannot be made absolutely atomic; checks reduce but cannot eliminate the final external state-change interval.

Real key/mouse interference, app changes, config reload, permissions loss and stop invalidate the execution token. Matched trigger releases are not treated as interference; additional modifier presses are. Paired left down/up and optional restoration share a cancellation lock: once stop/reload cancellation has returned, the old worker cannot post. Restoration is conditional on no recorded interference, unchanged expected cursor position, and current permissions/foreground. No activation, raising, or real dragging is performed. Stop gives owned swallowed keys a 500 ms drain window, then exits: indefinite held keys, permission revocation, tap disable, forced termination, or process failure cannot guarantee delivery pairing. No compensating synthetic keyboard events are sent.

A trigger that is refused after the shortcut matched posts no input, so the only feedback available is the helper's own: it records the message in `lastError` and draws a transient, non-activating notice panel (about 2.5 s, ignores the mouse, never activates another application, dismissed on stop). Raycast cannot be asked to render a toast at that moment: the extension process exits after spawning the service, and its `view`/`no-view`/`menu-bar` commands are unloaded between launches, so `showToast`/`showHUD` have no process to run in, and a deeplink-launched command would first require user confirmation. Only outcomes that posted no input produce a notice; a posted click whose optional cursor restoration was skipped is recorded in `lastError` without being presented as a failure. The notice panel is owned by the helper PID and is therefore excluded from the CG occlusion judgement (`WindowIdentity.resolve(ownPID:)`), so retriggering while a notice is visible cannot fail closed against the helper's own window.

The notice imitates Raycast's own HUD rather than inventing a look: a blurred dark capsule with a hairline highlight (the `.hudWindow` material) centred at the bottom of the display holding the pointer, an icon tile on the left, a 16 pt semibold white title and a 13 pt secondary line capped at two lines; the capsule's corner radius is always half its height, which is measured from the text. The icon is the extension's `appbind.png`, copied by the Raycast side to `notice-icon.png` in the support directory when the service starts; the helper reads it through `ServiceDirectory.optionalAsset(_:)`, which reports anything missing, non-regular, symlinked, hard-linked, foreign-owned, group/world writable, empty or over 512 KiB as absent. Without that asset the same tile shows a warning symbol, so the notice never depends on the file.

Validation uses Swift unit tests and filesystem-only temporary fixtures, not a real daemon, event listener, AX-driven click, or permission prompt. The notice panel itself was verified against the WindowServer from an unbundled process: it is composited on screen (observed in `CGWindowListCopyWindowInfo` while shown, 365×64 pt at the bottom of the display) and gone after its lifetime, and the measured body was rendered offscreen to confirm the capsule, icon tile and two-line typography. Live trigger-to-click behavior still requires manual verification.
