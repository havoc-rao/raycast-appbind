# AppBind 产品与实施计划

> 状态：P0/P1 安全诊断垂直切片实施中。原设计目标保留；实际完成状态以第 14 节为准。本次已获授权开始源码落盘。真实点击与常驻应用作用域热键未实现，不得将诊断成功解释为可以安全点击。

## 1. 产品定位

- **产品名**：AppBind；**标识**：`appbind`。
- **中文口号**：为每个 App 绑定你的操作。
- **英文描述**：App-aware hotkeys and window-relative actions。
- **命名说明**：名称尚未查重；公开分发前需核验同名产品、商标及相关标识。
- **核心模型**：App → Binding → Action。以应用的 **Bundle ID** 识别 App，不依赖易变化的显示名称或窗口标题。
- **目标体验**：同一快捷键在不同前台 App 中执行各自绑定的动作；未配置的 App 保留原按键行为。该目标由最终常驻 Helper 实现，不应与 Raycast 全局快捷键验证版混淆。

首个动作模式是在前台应用当前聚焦窗口内，按锚点和偏移计算位置，执行一次左键点击，再尽力恢复鼠标位置。适合位置相对稳定但缺少快捷键的按钮；不以识别按钮语义为前提。

## 2. 范围与非目标

### 2.1 最终 MVP 范围

1. 规则创建、读取、编辑、删除（CRUD）及单条启停。
2. 以当前前台 App 为作用域的快捷键，同键可跨 App 复用。
3. 五锚点窗口相对定位、单次左击、鼠标归位。
4. 位置捕获、仅标记预览、显式确认后的测试点击。
5. 冲突和权限诊断、失败原因提示。
6. Helper 生命周期管理、配置重载、协议及版本检查。

### 2.2 明确不做

- 后台窗口或不可见区域点击。
- 自动切换 Space、唤醒最小化窗口或激活其他 App。
- OCR、图像识别、拖拽、双击、多步宏。
- 绕过用户授权的控制。
- 保证光标不可见、保证所有 App 兼容、保证进程崩溃后必然恢复鼠标状态。

初期采用本地安装。Raycast 商店审核可行性、Helper 签名及公开分发方案单独核验，不作为已获支持的能力描述。

## 3. 系统架构

### 3.1 组件职责

| 组件 | 技术 | 计划职责 |
| --- | --- | --- |
| 配置界面 | Raycast TypeScript / React | 规则 CRUD、捕获/预览/测试入口、诊断、Helper 状态及管理 |
| 原生执行器 | Swift Helper | 通过 Accessibility（AX）查询应用和窗口，转换坐标，校验安全条件，通过 Core Graphics 移动鼠标、发送点击及归位 |
| 常驻热键服务 | 最终版本的 Swift Helper | 监听前台应用变化、处理应用作用域快捷键、透传非目标按键、串行执行动作 |
| 配置与通信 | 方案待原型确定 | 当前用户范围的规则持久化、动作请求、状态返回、版本及错误协议 |

Raycast 管理规则，Helper 执行规则；两者共享明确的数据模型，不把窗口操作逻辑散落到 UI。

### 3.2 轻量验证版与最终版的区别

**轻量验证版（P1）**：通过 Raycast 命令、Quicklink 或携带动作 ID 的 deeplink 调用一次性 Helper。用户在 Raycast 设置快捷键；Helper 可拒绝错误 App 中的动作，但 Raycast 全局热键仍会占用非目标 App 的原按键，**不等价于应用作用域热键**。

**最终版（P2）**：常驻 Helper 负责真正的应用作用域快捷键；Raycast 只负责规则管理和手动操作入口。未配置 App 不应被拦截相关按键，停用规则后应解除相应占用。

约束：

- Raycast `Action.shortcut` 仅是扩展界面中的操作快捷键，不能代替系统级热键服务。
- Background Refresh 不能作为常驻键盘监听服务。
- P0 比较热键注册与事件监听方案，验证按键透传、外部冲突、权限需求和 App 切换时序；不预先承诺某种 API 满足全部要求。
- IPC 和配置传输方式待定，限定当前用户权限，明确请求类型、动作 ID、协议版本、错误码和超时；拒绝非法来源或不合法请求，校验能力需在选定传输方式后验证。
- 调用 Helper 使用明确可执行文件和结构化参数，不拼接 shell 命令，不允许配置注入任意执行内容。
- 配置版本与 IPC 协议版本分别定义；遇到不兼容版本停止执行并提示处理方式，不静默猜测协议。

## 4. 首个执行模式：window-relative-click

### 4.1 坐标规范

以**包含标题栏的完整窗口**为基准，使用统一的屏幕逻辑坐标，不使用截图像素。统一规定 X 向右为正、Y 向下为正；各原生 API 的原点和方向必须转换到这一规范，不能直接假定 AX、AppKit、Core Graphics 返回值完全相同。

设窗口为 `(windowX, windowY, width, height)`，偏移为 `(offsetX, offsetY)`：

| 锚点 | 标识 | 基准点 |
| --- | --- | --- |
| 左上 | `top-left` | `(windowX, windowY)` |
| 右上 | `top-right` | `(windowX + width, windowY)` |
| 左下 | `bottom-left` | `(windowX, windowY + height)` |
| 右下 | `bottom-right` | `(windowX + width, windowY + height)` |
| 中心 | `center` | `(windowX + width / 2, windowY + height / 2)` |

目标点 = 基准点 + 偏移。右上锚点 `offset(-42, +76)` 的例子：

```text
x = windowX + width - 42
y = windowY + 76
```

窗口移动后重新读取几何，目标可跟随；窗口缩放时按锚点重新计算。应用内部布局变化、工具栏展开、响应式布局等不保证仍命中原按钮，用户需要重新捕获或调整规则。

### 4.2 必须验证的坐标问题

- AX / AppKit / Core Graphics 坐标转换与屏幕原点差异。
- 位于主屏左侧或上方的负坐标显示器。
- 多屏、跨屏窗口、不同缩放比例混合使用。
- 逻辑坐标与设备像素不能重复缩放。
- 非有限数值、非法尺寸、屏幕外或窗口外目标点必须拒绝。

## 5. 执行状态机与安全边界

### 5.1 标准流程

1. **捕获触发上下文**：保存触发时前台 App 的 Bundle ID、进程身份和聚焦窗口身份，不只记窗口标题。
2. **等待修饰键释放**：超时取消，避免把普通左击变成带修饰键的点击。
3. **重新校验身份**：仍须是原前台 App 和原聚焦窗口；应用切换、关窗、窗口身份不明确均取消，不重新选择一个“看起来相似”的窗口。
4. **重新读取窗口几何**：使用执行前的新位置和尺寸，而非缓存矩形。
5. **计算并验证目标**：检查有限数值、窗口/屏幕边界、可见性及遮挡；命中验证无法建立充分置信度时保守取消。
6. **保存鼠标位置**：在动作即将执行时记录原始位置。
7. **执行点击**：移动到目标，发送 mouseDown / mouseUp；发送前尽可能再次校验关键状态，缩短检查与使用之间的时间差。
8. **恢复鼠标**：正常情况下回到记录位置；如检测到用户主动移动鼠标，则取消未发生的点击或跳过强制归位，避免与用户争夺鼠标。
9. **返回结果**：明确区分成功、用户取消、安全拒绝、权限不足、通信失败及执行异常。

### 5.2 默认拒绝条件

只使用当前前台 App 的当前聚焦窗口。目标不明确、最小化、失焦、无权限、无窗口、越界或被遮挡时拒绝；不自动切 Space，不激活其他 App。

模态弹窗不能套用普通窗口的坐标。MVP 默认拒绝不明确的模态状态；若未来允许匹配模态窗口，必须明确识别该窗口并使用对应规则。

安全命中验证（例如结合 AX 命中信息与窗口可见性）能否跨应用可靠工作需 P0 验证；不能保证时应取消，而不是“试着点击”。这不构成对所有竞态或所有 App 的零误点保证。

### 5.3 并发、异常及用户干预

- 动作串行处理；触发队列必须有界。忙碌时拒绝或合并请求的具体策略待原型确定，不允许无限堆积过期点击。
- 抑制按键自动重复，测试快速连按和持续按住。
- 异常时尽力补发 mouseUp 并归位；进程崩溃或被强制终止时不承诺必然清理成功。
- 用户主动移动鼠标的检测方法、与 Helper 自发事件的区分方式待验证；检测不可靠时不宣称已实现用户干预保护。
- 光标移动可能可见；应用对合成事件的接受程度各异，不承诺全应用兼容。

### 5.4 Raycast 焦点恢复

通过 Raycast 发起捕获、预览、测试或动作时，需保留进入 Raycast 前的目标上下文，隐藏 Raycast 并验证目标已恢复为原前台 App 与窗口，之后才允许执行。不能以固定延时假定焦点已恢复；无法确认则取消，尤其不能误点 Raycast 自己的窗口。该流程不授权激活任意其他 App，也不绕过前台窗口约束。

## 6. Raycast 界面与操作流程

### 6.1 主要入口

| 入口 | 计划用途 |
| --- | --- |
| Manage Bindings | 按 App 查看、搜索、编辑、删除和启停规则，显示热键和诊断信息 |
| Create Binding | 引导选择目标 App 并建立绑定 |
| Run Action | 选择动作手动执行，仍执行全部前台与安全校验 |
| Helper Status | 查看运行状态、版本、权限、配置状态，提供启动/停止/重载及故障指引 |

### 6.2 创建流程

1. 选择 App（保存 Bundle ID）、填写动作名、设置热键。
2. 选择模式 `window-relative-click` 和五种锚点之一。
3. **Capture Position**：隐藏 Raycast；用户把鼠标指向目标按钮，按专用确认键捕获当前位置，读取目标窗口并计算偏移。此操作**不实际点击**，支持取消和超时；捕获确认键与动作热键隔离，捕获期间不触发普通绑定。
4. **Preview Target**：仅标记计算出的目标点，不点击。覆盖层不得阻挡点击或抢走目标焦点；如何实现和验证留给原型。
5. **Test Click**：先向用户明确提示将发生真实点击，显式确认后隐藏 Raycast、完成焦点及安全检查，再执行一次测试。
6. 校验数据和冲突后保存；修改规则也沿用相同校验。

### 6.3 字段

| 字段 | 含义/默认值 |
| --- | --- |
| name | 动作名称 |
| app | 目标 App，持久化为 Bundle ID |
| hotkey | 主键及修饰键 |
| scope | `frontmost-app`，MVP 固定 |
| window | `focused`，MVP 固定 |
| mode | `window-relative-click` |
| anchor | 五种锚点之一 |
| offset | X/Y 逻辑坐标偏移，支持捕获及手动调整 |
| button | `left`，MVP 固定 |
| restore | `true`，默认归位 |
| enabled | 规则启停 |

关键安全选项可固定开启，不为追求灵活性开放跳过安全检查的开关。

## 7. 数据模型与配置约束

### 7.1 JSON 示例

以下为 v1 配置结构；当前严格校验契约见第 14 节与 [CONTRACT.md](<CONTRACT.md>)：

```json
{
  "schemaVersion": 1,
  "bindings": [
    {
      "id": "toggle-sidebar",
      "name": "打开侧边栏",
      "enabled": true,
      "application": {
        "bundleId": "com.example.app"
      },
      "trigger": {
        "type": "hotkey",
        "key": "k",
        "modifiers": ["control", "option"],
        "scope": "frontmost-app"
      },
      "action": {
        "type": "window-relative-click",
        "window": "focused",
        "anchor": "top-right",
        "offset": {
          "x": -42,
          "y": 76
        },
        "button": "left",
        "restoreCursor": true
      }
    }
  ]
}
```

### 7.2 校验与更新

- 规则 ID 唯一，必填项、枚举、类型和 Bundle ID 格式需校验。
- 同 App 内重复热键拒绝，不同 App 可复用。规范化修饰键集合后再比较，避免不同排列绕过检查。
- 外部 App 或系统热键冲突尽量检测和提示，但不保证完整枚举；最终以原型和实际使用测试为准。
- `key` 采用逻辑字符还是物理键码尚未决定；示例 `k` 不意味着策略已经定案。需测试不同键盘布局、输入法及布局切换。
- 坐标、偏移和窗口几何必须是有限数值；偏移可为负，不等于允许越界点击。具体限值在实现前确定。
- 配置以原子方式更新，完整验证后再替换运行时快照，避免读取到半写入内容。坏配置不激活；保留旧有效配置还是停止相关规则需明确提示，不静默改变动作。
- 配置迁移、重载和失败回滚应有版本规则，协议不兼容时拒绝执行。

### 7.3 未来扩展（不属于当前 MVP）

仅预留概念：`accessibility-press`、`menu-item`、`keystroke`、`sequence`。各模式需要独立能力检测、安全模型和验收，不能当作当前已支持功能。

## 8. 权限、隐私与本地安全

- **辅助功能权限**：用于 AX 查询和自动化控制；需针对实际执行的进程验证并引导授权。
- **输入监控权限**：是否需要取决于最终热键 API 和事件监听方案，必须原型验证，不统一声称不需要或必然需要。
- **屏幕录制权限**：纯几何查询与点击通常不需要；未来如加入屏幕图像捕获，应另行说明并申请。Capture Position 仅记录指针位置，不等同截图。
- 权限说明应展示实际需要授权的进程路径；一次性 Helper、常驻 Helper 和 Raycast 的权限归属需分别验证，不能只笼统要求给 Raycast 授权。
- 权限撤回后停止相关执行并提供诊断，不持续重试点击。
- 不记录文本输入；日志默认不收集敏感窗口标题，可记录动作 ID、错误类别及必要的非敏感诊断。
- 配置、日志及 IPC 限定当前用户访问；不通过配置或 IPC 接受任意 shell 执行。

## 9. 实施阶段与验收门槛

默认顺序：**先执行器和热键可行性验证，再配置闭环，再常驻服务，最后稳定性与分发**。下表是完整阶段门槛，不是完成记录；本次基础切片状态单独列于第 14 节。

| 阶段 | 计划工作 | 验收标准 |
| --- | --- | --- |
| P0：Swift 与热键原型 | 验证 AX 窗口身份/几何、坐标转换、点击归位、遮挡命中、用户移动检测；比较热键注册/事件监听 | 至少覆盖原生及 Electron 样例 App；测试多屏与失焦；无法安全判定时失败关闭；记录透传、冲突、权限和 App 切换结果，明确不可保证之处 |
| P1：Raycast 配置闭环 + 一次性 Helper | 完成 CRUD、捕获、预览、测试、手动执行及结构化调用 | 用户无需手改配置可创建并测试规则；捕获不点击、预览不阻挡、测试须确认；隐藏 Raycast 后校验焦点，不误点 Raycast；明确标注全局快捷键限制，不称已完成前台作用域 |
| P2：常驻热键完整版 | 常驻 Helper、应用作用域处理、启停、重载、版本握手和 IPC | 跨 App 同键执行不同动作；其他 App 原按键不被占用；停用即解除相应作用；快速切换 App 不执行旧动作；非法 IPC 与不兼容版本被拒绝；服务状态可诊断 |
| P3：稳定性与分发 | 自动化/人工测试，重启与可选登录启动，撤权与升级，兼容性及安装文档 | 验证所声明的 macOS 版本和 CPU 架构；重启/升级后状态明确；撤权即停；提供安装、授权、排障、卸载说明；卸载不遗留服务或登录项 |

P0 的安全性或透传验证未通过时，应缩小支持范围或调整技术方案，不以跳过检查推进最终 MVP。登录启动方案需先获得产品层面的选择，不能默认静默安装。

## 10. 测试矩阵

以下均为待执行的验收用例，不能视为测试已通过。

| 场景 | 预期行为/检查点 |
| --- | --- |
| 窗口移动、缩放 | 读取最新几何，五锚点计算正确；布局改变不误宣称仍匹配按钮 |
| 多屏、负坐标、混合缩放、跨屏窗口 | 统一逻辑坐标，定位及归位无比例或原点偏差 |
| 同 App 多窗口 | 仅触发时的原聚焦窗口可执行，不落到其他窗口 |
| 触发后切 App 或关窗 | 身份复核失败则取消，不使用旧位置 |
| 模态弹窗、遮挡 | 拒绝不明确模态/遮挡目标，不套用普通窗口坐标 |
| 最小化、无窗口、其他 Space | 拒绝，不自动恢复窗口或切换 Space |
| 修饰键长时间未释放 | 超时取消，不产生带修饰键点击 |
| 连按、按住自动重复 | 串行、有界，抑制重复，不累积滞后点击 |
| 执行前后用户主动移动鼠标 | 按验证后的策略取消或跳过强制归位，不与用户争夺指针 |
| 权限撤回 | 停止相关执行，给出实际进程的授权诊断 |
| 同键跨 App | 正确执行各自绑定；同 App 重复配置被拒绝 |
| 未配置 App 的按键透传 | P2 不占用原按键；P1 明确记录不满足该目标 |
| 输入法、键盘布局变化 | 验证最终选定的逻辑字符/物理键码语义及冲突判断 |
| 捕获、预览、测试以及 Raycast 焦点恢复 | 捕获不点击、确认键隔离、覆盖层不阻挡，真实点击需确认且不误点 Raycast |

## 14. 可执行工程方案与真实状态

### 14.1 保守且可逆的默认决策

- 本地开发，最低编译部署目标 macOS 13；本机 arm64 编译结果不代表 Intel 或旧 macOS 已验收。
- 配置与请求协议均为 v1，独立检查版本；不自动迁移未知版本。
- 当前采用一次性 CLI 的 stdin/stdout JSON，不开放 socket；未来常驻 IPC 必须另做来源认证与生命周期设计。
- 键值暂限小写 ASCII 字母或数字，表示逻辑字符；本次不注册任何全局键。物理键码、多布局语义留待热键原型。
- 同 App 相同规范化快捷键（含停用规则）拒绝；不同 App 可复用；停用仍保留热键槽避免重新启用产生隐式冲突。
- 配置最多 1000 条、1MiB；偏移绝对值不超过 100000 且必须有限；固定左键与归位 true；拒绝未知字段，不默默忽略拼写错误。
- 配置写入使用同目录临时文件、0600、同步落盘、原子 rename；独占锁保护读改写，锁忙拒绝，不自行删除疑似过期锁；已有坏配置不会重置为空。
- 所有执行请求固定 SAFETY_NOT_IMPLEMENTED，且不发送 CGEvent。遮挡验证、持久窗口身份、修饰键释放与用户干预尚未可靠实现，不能以延迟或仅检查 Bundle ID 替代。
- dry-run 只输出几何诊断，不是安全点击授权；Raycast 面板占焦点时拒绝不匹配目标，不隐藏面板后盲猜原窗口。

### 14.6 取点遮罩（capture）实现状态

- 协议：[docs/CONTRACT.md](<CONTRACT.md>)「Capture (point picking overlay)」；capture 仅接受 bundleId+anchor，不带配置与绑定 ID，不接收客户端窗口几何。
- 交互：Helper 显示多屏消隐遮罩并在目标窗口区域留亮描边；准星与实时锚点/偏移读数跟随指针；Enter 确认、Esc 取消、方向键微调 ±1（Shift ±10）；无点击、无真实光标移动、无其他 App 激活；120 秒无交互超时取消。
- 确认路径：确认瞬间重读目标 App 聚焦窗口 AX 几何，校验有限值、窗口半开包含与显示器包含，随响应回传 bundleId/pid/frame/anchor/offset/target/durationMs。
- Raycast：transport 严格校验 capture 请求/响应，capture 使用长超时；创建/编辑表单通过“从窗口取点…”动作调用（先关闭 Raycast 面板，`popToRootType: Suspended` 保留表单为返回视图），回填锚点与偏移，保存仍由用户显式完成；取点结束（确认/取消/失败）后通过 LaunchServices 重新激活 Raycast（`open -a Raycast`）自动重开面板，提示在面板出现后展示。
- 取消/失败不写回表单；未授权 AX 时返回 PERMISSION_DENIED 且不显示遮罩；目标 App 未运行返回 APP_NOT_RUNNING。
- 自动验证（2026-09-29）：Swift 核心新增锚点/反向偏移/坐标转换/请求形状测试，Swift 22/22 通过；Raycast 新增 capture 校验与超时策略测试，15/15 通过；根级 smoke 13/13、跨语言对齐 25/25 通过。实测：malformed capture 在任何遮罩出现前被拒绝；合法 capture 在无 AX 权限或目标未运行时快速失败关闭，不阻塞。
- overlay 键盘/焦点交接、真实 AX 权限下的遮罩显示、取点结束后自动重开 Raycast 面板（`open -a Raycast` 激活 + `popToRootType: Suspended` 保留表单视图）与表单恢复、多屏混合缩放为待人工验收；取点只写回表单，保存与点击仍由用户显式完成。
