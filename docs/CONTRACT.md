# AppBind v1 contract

新增后台服务使用独立 argv 控制协议，见 [后台服务说明](<background-service.md>)。下文旧 stdin 协议仍保持诊断/录制用途，execute 固定拒绝；这不代表显式启动的后台服务禁用执行。规则范围与配置 schema 不变。

Configuration uses the exact schemaVersion:1 / bindings structure illustrated in [plan section 7.1](<plan.md>). No optional binding fields. Reject unknown fields at every level. id: ASCII [a-z0-9][a-z0-9-]{0,63}; name: nonempty trimmed <=120 characters; bundleId: ASCII segments [A-Za-z0-9-]+ separated by dots (at least two), <=255 characters. Max 1000 bindings, unique IDs. key: single lowercase ASCII a-z or 0-9 (logical character, not physical keycode; no hotkey registration yet). modifiers: unique, nonempty subset of control/option/shift/command. Duplicate normalized (bundleId, key, sorted modifiers) is rejected including disabled rules. Offset finite and abs <=100000. restoreCursor must be true; fixed enums as in example. Config max 1MiB UTF-8. Unknown numeric schema version is rejected with UNSUPPORTED_VERSION (wrong types remain INVALID_CONFIG), no migration yet. Name length counts UTF-16 code units for cross-language parity; trimming uses ECMAScript String.trim whitespace (including U+FEFF, excluding U+0085), not Foundation's broader whitespace set.

Helper is a one-request process. stdin is one UTF-8 JSON object, <=1MiB, EOF terminated; stdout exactly one JSON response plus newline; diagnostics only stderr. No shell parsing. All requests: {"protocolVersion":1,"command":"status"|"inspect"|"dry-run"|"capture"|"record-shortcut"|"execute", "config"?:Config,"bindingId"?:string}. Reject unknown keys. status, inspect and record-shortcut accept only protocolVersion/command; dry-run and execute require config and bindingId. capture requires bundleId and anchor instead of config/bindingId (see capture section). Helper reads live frontmost window for dry-run, never accepts client-provided target geometry. Execute always fails closed in this slice even with valid input. No event posting, cursor movement, AX prompting, service installation, app activation or focus restoration.

Responses: {"protocolVersion":1,"ok":boolean,"data"?:object,"error"?:{"code":string,"message":string}}; exactly data on success or error on failure. Exit 0 success, 1 application/request error. Errors: INVALID_REQUEST, UNSUPPORTED_VERSION, INVALID_CONFIG, BINDING_NOT_FOUND, BINDING_DISABLED, PERMISSION_DENIED, NO_FRONTMOST_APP, APP_MISMATCH, APP_NOT_RUNNING, UNSAFE_TARGET, USER_CANCELLED, SAFETY_NOT_IMPLEMENTED, INTERNAL_ERROR. Client transport errors: HELPER_UNAVAILABLE, HELPER_TIMEOUT, INVALID_RESPONSE. status data includes helperVersion, accessibilityTrusted, executionEnabled:false. inspect returns frontmost bundleId/pid and focused window frame if safe to query; no titles. dry-run validates config, enabled binding, frontmost bundleId, AX focused window and finite geometry, half-open window/display containment, returns target point and diagnosticOnly:true. Dry-run does NOT attest safety of a click; identity persistence/occlusion/user intervention are unfinished.

Geometry core: logical desktop coordinates X-right Y-down, no backingScaleFactor multiplier. AX position/size feed diagnostic geometry; display bounds from CGDisplayBounds, all active displays, not AppKit frame. Negative origins supported. Width/height >0, finite arithmetic, abs origins/dimensions <=100000. Rect contains left/top inclusive, right/bottom exclusive; offsets on right/bottom must move inward. Five anchors as in plan.

## Shortcut recording

Request: {"protocolVersion":1,"command":"record-shortcut"}, no additional fields. Success data: {"key":"k","modifiers":["control","option"]}. Keys are lowercase ASCII a-z or 0-9; modifiers are a nonempty unique subset of control/option/shift/command. Invalid responses are rejected before changing the form.

An explicit form action opens an accessory helper recording window. Only local keyboard events are consumed; there is no global monitor, event posting, AX permission request, hotkey registration, or binding execution. A valid combination becomes a preview candidate, not an immediate result. Further combinations replace it; unmodified Enter or the Confirm button commits it. Invalid input invalidates the candidate until re-recorded. The form shows a read-only shortcut and a fixed recording action; confirmed candidates are checked against same-app bindings (including disabled entries, excluding the edited entry) before refill, with conflict feedback and no mutation on rejection. Saving remains explicit and performs the existing locked validation again. Esc, timeout, or sustained focus loss returns USER_CANCELLED and preserves prior fields. Unsupported keys leave the recorder open with feedback. System-reserved shortcuts may be intercepted by macOS. Interactive transport timeout is 150s; the helper session must finish earlier. Real keyboard layouts, focus handoff and Raycast refill require manual acceptance.

## Capture (point picking overlay)

Purpose: let the user point at a target location and get anchor+offset back for the form. It never clicks, never moves the cursor, never hides/activates other apps, and does not open execute. The only activation is the helper itself becoming active, justified by the explicit user gesture "pick point".

Request: {"protocolVersion":1,"command":"capture","bundleId":string,"anchor":one-of-five}. No config/bindingId: identity comes from the Raycast form (auto-filled from frontmost app or typed manually, already validated). Helper never accepts client-provided window geometry; it reads live AX geometry.

Fail-closed preconditions (checked before the overlay appears; otherwise structured error, exit 1): request shape and anchor enum; bundleId format; AXIsProcessTrusted() else PERMISSION_DENIED (never prompt); target app running else APP_NOT_RUNNING; target app's focused window retrievable with valid geometry else UNSAFE_TARGET. The focused window is read without requiring the target app to be frontmost; if the AX query is unavailable, cancel instead of guessing.

Overlay behavior: one borderless dimming window per active display (high window level), target window region kept undimmed with an animated highlight (rounded cutout, breathing yellow glow halo, corner brackets); crosshair, full-display alignment guides and live readouts (anchor, X/Y offset banner, pointer CG coordinate pill) following the pointer, crosshair turning yellow while the pointer is inside the target window; display origin conversion: NSEvent.mouseLocation is bottom-left Cocoa, convert to CG top-left using main display height; logical units, no scale multiplication. A 30 fps pulse loop redraws the overlays while picking and is invalidated when the session finishes. Helper runs as accessory app (no Dock tile) and its overlay window becomes key. Keyboard on overlay key window: Enter confirms, Esc cancels; arrow keys nudge the picked target by 1 logical unit (Shift ±10) while keeping it inside window and display bounds. Left-click confirms the displayed selection (including keyboard nudges) through the same path as Enter, on mouse-up; the overlay consumes both down/up rather than forwarding them. Tracking areas receive pointer motion on every overlay, including non-key displays. CG global rectangles are converted to Cocoa window frames and display-local unflipped drawing coordinates. No clicks sent to target apps, no CGEvent posting, no real cursor movement.

Confirm: re-read the target window AX frame, compute the anchor base point, target = displayed selection (pointer location plus any keyboard nudges), verify finite values, offset abs<=100000, target inside window (half-open) and inside an active display; then respond. Success exit 0.

Cancel: Esc, overlay losing key/active status, or inactivity timeout (120s default, overridable in tests) → USER_CANCELLED, exit 1.

Response data (ok): {"bundleId":string,"pid":number,"frame":{"x","y","width","height"},"anchor":anchor,"offset":{"x","y"},"target":{"x","y"},"durationMs":number}. Raycast fills the form from this and the user still explicitly saves. Overlay interaction with real AX permission, focus handoff after closing Raycast panel, and multi-display behavior are manual-verification territory.

Raycast stores config in environment.supportPath/config.json via validated same-directory temporary file mode 0600, directory 0700, fsync and atomic rename. Exclusive lock serializes read/modify/write; busy errors never overwrite. Invalid existing config is an error, not replaced with defaults; missing config alone becomes empty. Stale lock is reported and manual removal only after verifying no writer. Helper path is an explicit absolute user preference. spawn/execFile with no shell and stdin JSON, bounded timeout/output. Panel dry-run can be refused due to Raycast focus and must explain limitation; do not hide and guess prior window. UI shortcut is not a global app-scoped hotkey. 后台服务已新增同 UID 本地 IPC 与受保护的执行路径，具体协议和限制见后台服务说明；它不是旧 stdin execute 的放开。
